# AutoService -- система за управление на автосервиз

## 1. Описание на проекта

**AutoService** е уеб приложение за управление на дейността на
автосервиз. Системата позволява на клиентите да регистрират профил, да
добавят своите автомобили, да разглеждат предлаганите услуги и да
записват час за обслужване. Администраторът управлява основната
информация и следи записаните часове.

Проектът е разработен като курсов проект с Python и Flask.

## 2. Основни функционалности

### Клиенти

-   Регистрация и вход в системата.
-   Управление на личния профил.
-   Добавяне, преглед и редактиране на автомобили.
-   Разглеждане на активните услуги на автосервиза.
-   Записване и преглед на часове за обслужване.
-   Добавяне на оценка и коментар след приключен час.

### Администратор

-   Достъп до административен панел.
-   Преглед на обобщена информация за клиенти, автомобили и часове.
-   Преглед и управление на записаните часове.
-   Промяна на статуса на час и назначаване на служител.
-   Управление на услугите и служителите.
-   Преглед на клиентските отзиви.

### Правила и проверки

-   Паролата при регистрация трябва да отговаря на зададените изисквания
    за дължина.
-   Автомобилът е свързан със своя собственик.
-   Не се допуска записване на повече от един час за една и съща дата и
    час.
-   Един и същ час може да бъде оценен само веднъж и само след
    приключването му.
-   Оценката е в диапазона от 1 до 5.
-   При добавяне на автомобил се проверяват регистрационният номер и
    годината на производство.

## 3. Използвани технологии

-   **Python** -- основен програмен език.
-   **Flask** -- уеб framework.
-   **Flask-SQLAlchemy / SQLAlchemy** -- работа с релационната база
    данни.
-   **Flask-Login** -- удостоверяване и управление на потребителските
    сесии.
-   **Flask-WTF / WTForms** -- уеб форми и валидация.
-   **Flask-Migrate / Alembic** -- миграции на базата данни.
-   **PostgreSQL** -- релационна база данни.
-   **Docker и Docker Compose** -- контейнеризация и стартиране на
    услугите.
-   **Nginx** -- уеб сървър и обратен прокси.
-   **Gunicorn** -- WSGI сървър за Flask приложението.
-   **pytest** -- автоматизирани тестове.

## 4. Модел на данните

Базата данни съдържа следните основни модели:

  Модел           Предназначение
  --------------- -----------------------------------------
  `User`          Потребителски профили и роли
  `Vehicle`       Автомобили на клиентите
  `Appointment`   Записани часове за обслужване
  `Service`       Услуги, предлагани от автосервиза
  `Employee`      Служители на автосервиза
  `Review`        Оценки и коментари за приключени часове

Основните връзки между моделите са представени в UML диаграмата
`AutoService.drawio`.

## 5. Стартиране на проекта с Docker

### Предварителни изисквания

Необходимо е да са инсталирани: - Docker Desktop; - Docker Compose
(включен в актуалните версии на Docker Desktop).

### Стъпки

1.  Клонирайте или копирайте проекта на компютъра.
2.  Създайте `.env` файл в главната директория.
3.  Задайте необходимите настройки за базата данни и приложението. Не
    публикувайте реални пароли или секретни ключове.
4.  Стартирайте контейнерите:

-   docker compose up --build -d

5.  Проверете състоянието им:

-   docker compose ps

6.  Изпълнете миграциите:

-   docker compose exec web1 flask db upgrade


7.  Отворете приложението в браузъра:

-   http://localhost:8080

-   https://localhost:8443/

-   За преглед на логовете отворете Dozzle в браузъра:
    http://localhost:9999/

-   За спиране на услугите:
    docker compose stop

> Забележка: `docker compose down` спира и премахва контейнерите, но не
> изтрива именуваните Docker volumes. Не използвайте
> `docker compose down -v`, ако искате да запазите данните в базата.

## 6. Стартиране в локална Python среда

Ако желаете да стартирате приложението без Docker:

1.  Създайте и активирайте виртуална среда:

``` powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

2.  Инсталирайте зависимостите:

``` powershell
pip install -r requirements.txt
```

3.  Конфигурирайте променливите на средата в `.env`, включително
    връзката към PostgreSQL и секретния ключ.
4.  Изпълнете миграциите:

``` powershell
flask db upgrade
```

5.  Стартирайте приложението:

``` powershell
python run.py
```

При локално стартиране адресът и портът зависят от конфигурацията на
Flask.

## 7. Миграции на базата данни

За прилагане на наличните миграции:

``` powershell
flask db upgrade
```

За генериране на нова миграция след промяна на моделите:

``` powershell
flask db migrate -m "Описание на промяната"
```

След преглед на генерирания migration файл миграцията се прилага с:

``` powershell
flask db upgrade
```

Миграционните файлове се съхраняват в директорията `migrations`.

## 8. Стартиране на автоматизираните тестове

От главната директория на проекта и при активирана виртуална среда
изпълнете:

``` powershell
python -m pytest
```

За по-подробен резултат:

``` powershell
python -m pytest -v
```

Тестовете проверяват основни части от приложението, включително
удостоверяване, автомобили, часове, административни функционалности,
услуги и отзиви.

## 9. Резервно копие на базата данни

Проектът използва PostgreSQL. Резервно копие във формат, подходящ за
`pg_restore`, може да бъде създадено от контейнера на базата данни:

``` powershell
docker compose exec -T db pg_dump -U autoservice_user -d autoservice_db -Fc -f /tmp/autoservice_backup.dump
```

Копиране на архива от контейнера към текущата директория на проекта:

``` powershell
docker cp autoservice_db:/tmp/autoservice_backup.dump .\autoservice_backup.dump
```

Преди възстановяване винаги проверявайте архива и се уверявайте, че
разполагате с отделно резервно копие на текущата база данни.

## 12. Стартиране на проекта в GitHub Codespaces

Проектът може да бъде стартиран директно в GitHub Codespaces, без
необходимост от локална инсталация на Python и Docker Desktop.

### 12.1 Създаване на Codesapce

-   В хранилището на AutoService,
-   Натисенте бутона Code,
-   Изберете раздела Codespaces,
-   И натиснете Create cidespace on main , като изчакате средата да се зареди.

### 12.2 Конфигуриране на средата

-   В терминала на Codespaces нaпишете "cp .env.example .env",
-   След това отворете файла със "nano .env" и му задайте собствени стойности за секретен ключ и парола за PostgreSQL,
-   Уверете се че паролата съвпада със DATABASE_URL,
-   При стартиране чрез Docker Compose приложението използва вътрешния адрес db:5432.

### 12.3 Генериране на тестови SSL сертификати

-   Nginx използва SSL сертификати от директорията certificates.
-   Създайте тестови самоподписани сертификати:
    ```
    mkdir -p certificates
    ```
    
    ```
    openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
      -keyout certificates/autoservice.key \
      -out certificates/autoservice.crt \
      -subj "/CN=localhost"
    ```
### 12.4 Стартиране на контейнерите

-   Изграждане и стартиране на услугите:
    docker compose up --build -d
-   Проверка на тяхното състояние:
    docker compose ps
-   Изпълняване на миграциите към базата данни:
    docker compose exec web1 flask db upgrade

### 12.5 Отваряне на приложението

1.  Отворете раздел Ports в Codesapces.
2.  Намерете порт 8080 - HTTP
3.  Порт 8443 - HTTPS
4.  За преглед на логовете отворете порт 9999 - Dozzle
5.  Изберете Open in Browser Или натиснтете CTRL + Left Mouse Button на линка на съответния порт.

-   За спиране на контейнерите:
    docker compose stop

### 12.6 Важни белешки за CodeSpaces

-   Базата данни в Codespaces е отделна то локалната,
-   Регистрациите и записите от локалната база данни не се прехвърлят.
-   За създаване на админисраторски профил напишете:
    python create_admin.py
-   За добавяне на услугите към базата данни напишете:
    python seed_services.py
